## 2. 方向重述

上一版「我们帮用户定好首屏主次」→ 现改为：

> **把展示主动权交给用户**：提供好看的布局预设（Demo Gallery），用户一键套用；在此基础上再支持自由调整（显隐、位置、跨度）。视觉提升 = 皮肤系统 + 卡片/图表一致性 + 布局能力，而不是替用户改死一张首页。

默认打开仍可用「经典」预设（即接近现在的布局），保证老用户无感。

---

## 3. 可行性评估

### 3.1 结论：**可行，建议分两档落地**

当前首页是写死的 JSX 网格（`Index.tsx` 约 40 行），图表已是独立组件，**抽成「组件注册表 + 布局配置」在工程上很自然**，不必重写业务逻辑。

项目里已有 `react-resizable-panels`，但更适合做「看板积木」的是 **布局配置驱动渲染**；拖拽网格若需要，可后续引入 `react-grid-layout`（业界常见），不是必须一期就上。

### 3.2 两档能力对比

| 能力档 | 用户能做什么 | 工程量 | 风险 | 建议 |
|--------|--------------|--------|------|------|
| **L1 预设画廊** | 在 4～6 套精美预设里选一套并应用 | 中（约 1.5～2.5 天） | 低 | **一期必做** |
| **L2 自由编排** | 拖拽改位置/大小、显隐组件、保存为我的布局 | 较高（约 +2～4 天） | 中（响应式、图表 resize、配置迁移） | **一期可做轻量版，或紧接 L1** |

「自由更改布局」若理解为完全拖拽画布，一期全做会拖慢皮肤与一致性工作。更稳的路径：

1. **先做 L1**：主动权先交给用户（选预设 = 已有选择权）  
2. **再做 L2 轻量**：每套预设内可「显示/隐藏模块」+「简单调换左右」；完整拖拽网格放到二期  
3. 或你明确要求一期就要拖拽 → 可行，但工期与测试量明显上升（见 §6）

### 3.3 技术可行点（有利）

- 现有组件（KPI、收入、客户、地图、毛利、费用）边界清晰，可注册为 Widget  
- 布局可用纯 JSON 描述，存 `localStorage`（一期够用，无需后端）  
- 预设 = 几份写死的 JSON + 缩略预览图（可用静态示意图或截图）  
- 换肤与布局正交：换皮肤不改布局 JSON  

### 3.4 主要风险与对策

| 风险 | 说明 | 对策 |
|------|------|------|
| 图表在 resize 后空白 | Recharts 需容器尺寸变化时触发 resize | Widget 外壳统一 `ResponsiveContainer` + resize observer |
| 小屏乱 | 拖拽网格在手机上难用 | `<lg` 强制单列堆叠；编辑布局仅桌面启用 |
| 配置版本升级 | 以后加新组件，旧 JSON 缺字段 | `layoutVersion` + 迁移函数，未知 id 忽略 |
| 预设「好看」主观 | 几套预设质量决定口碑 | 预设由产品定，数量宁少勿滥（4 套够） |
| 范围膨胀 | 自由布局易做成「低配 Grafana」 | 一期只覆盖**首页看板** 6 个模块，不做跨页自由拼 |

### 3.5 不建议一期做的

- 深色主题  
- 云端账号级布局同步（可后置 API）  
- 任意嵌套、任意第三方 iframe 组件  
- 为布局重写管理报表 / 查询平台（那些页仍固定结构，只跟皮肤）

## 4. 布局模型（草案）

### 4.1 Widget 注册表（固定集合）

| id | 组件 | 默认占位（12 栏栅格） | 备注 |
|----|------|----------------------|------|
| `kpi` | `KpiCards` | 12×固定高 | 建议始终置顶或允许藏 |
| `revenue` | `RevenueChart` | 8×中高 | 可点进查询 |
| `customers` | `TopCustomers` | 4×中高 | |
| `map` | `ChinaMapChart` | 4×中高 | **必须保留在可选组件中** |
| `margin` | `ProductMarginChart` | 4×中高 | |
| `expense` | `ExpensesChart` | 4×中高 | |

### 4.2 布局配置形状（示意）

```json
{
  "version": 1,
  "presetId": "classic",
  "widgets": [
    { "id": "kpi", "visible": true, "colSpan": 12, "order": 0 },
    { "id": "revenue", "visible": true, "colSpan": 8, "order": 1 },
    { "id": "customers", "visible": true, "colSpan": 4, "order": 2 },
    { "id": "map", "visible": true, "colSpan": 4, "order": 3 },
    { "id": "margin", "visible": true, "colSpan": 4, "order": 4 },
    { "id": "expense", "visible": true, "colSpan": 4, "order": 5 }
  ]
}
```

渲染：按 `order` 排序 → CSS Grid 12 栏 → `colSpan` 映射 `col-span-*`。  
**L1 只切换整份 widgets；L2 再允许改 order / colSpan / visible。**

### 4.3 预设画廊（Demo，建议一期 4 套）

名称可再定，结构示意：

| 预设 ID | 名称 | 叙事 | 与现状关系 |
|---------|------|------|------------|
| `classic` | 经典总览 | KPI + 收入/客户 + 地图/毛利/费用 | **≈ 当前布局，默认** |
| `trend-focus` | 趋势优先 | KPI + 收入拉满宽；下方客户+费用；地图/毛利次行 | 偏看趋势 |
| `geo-structure` | 区域与结构 | KPI + 地图加大；收入与费用并排；客户/毛利次之 | 强调地图 |
| `compact` | 紧凑决策 | KPI + 收入/客户；地图与费用；毛利可默认隐藏 | 信息更少 |

入口：顶栏「功能」或看板右上「布局」→ 打开画廊（大预览卡 + 一键应用）。  
应用后写入 localStorage；提供「恢复经典」。

## 5. 与「紫色皮肤 / 多皮肤」如何并存

两者解耦：

| 系统 | 存什么 | 影响什么 |
|------|--------|----------|
| **Theme** | `violet` / `slate` / `teal` | CSS 变量、图表色板 |
| **Layout** | presetId + widgets[] | 首页模块排列与显隐 |

一期皮肤：

- 默认 `violet`（精修，不推倒）  
- 可选 `slate`、`teal`  
- **不做 ink 深色**

视觉提升在皮肤侧仍做：弱化 glow、统一卡片与图表 token、换肤入口——**但不靠改死首页排版来体现「高级感」**。

## 6. 分期计划（修订）

### 阶段 0 — 基线（已部分完成）

- [x] 去掉右上角重复「演示数据」  
- [ ] 文档与范围对齐（本文）

### 阶段 A — 主题系统（约 1 天）

- A1 `violet` token 精修（去过度 glow，保留紫系）  
- A2 `data-theme` + localStorage：`violet` / `slate` / `teal`  
- A3 功能菜单「外观」入口  
- A4 硬编码 `hsl(262…)` 逐步改为变量（至少按钮/芯片/头部）

**不改 Index 排版。**

### 阶段 B — 布局 L1：预设画廊（约 2 天）★ 核心新方向

- B1 Widget 注册表 + `DashboardCanvas` 按 JSON 渲染（默认 JSON = 当前布局）  
- B2 内置 4 套预设 + 画廊 UI（预览 + 应用）  
- B3 localStorage 持久化；「恢复经典」  
- B4 地图始终作为可选项且在至少 2 套预设中出现（含 classic）  
- B5 小屏单列降级  

**验收：** 用户不写代码也能换一种「好看的首页」；默认与现在几乎一致。

### 阶段 C — 布局 L2 轻量自由（约 1.5～2.5 天，可与 B 拆开确认）

- C1 编辑模式：显示/隐藏模块  
- C2 调整跨度（4 / 6 / 8 / 12）与上下顺序（上移/下移按钮即可，**可不做拖拽**）  
- C3 「另存为我的布局」（仍 localStorage）  
- C4 （可选加项）`react-grid-layout` 拖拽 —— **单独立项，避免拖垮一期**

### 阶段 D — 图表一致性与子页跟皮肤（约 1 天）

- 图表色走 theme；管理/清洗/查询页跟皮肤，布局仍固定
